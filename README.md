# hxyfront-62008 烟花燃放脚本 · 变更单台

在原烟花编排页基础上改造的**变更单台**：对已签批节点的修改先生成变更单，经传播校验与
双人确认后才落为新签批版本，旧版本全程留档，数据在浏览器重开后仍可查。

## 预置数据

- **3 段节目**：序章 Intro（0–75s）、主歌 Chorus（75–200s）、终章 Finale（200–260s）
- **6 个节点**：记录点位、点火毫秒、持续毫秒、音乐拍点、执行状态与签批版本（N1 已执行）
- **4 个点位**：A / B / C / D，在平面图中固定布局

## 业务流程

1. 点击时间轴或点位图中的**未执行节点**发起变更，锚点节点之外不可直接改脚本。
2. 修改锚点点火时间后，系统沿**同一点位后续未执行节点逐项平移相同偏移**（已执行与其他点位不动），预览中以虚线标记展示。
3. 提交时逐项校验，任一节点触发任一规则则**整张变更单退回、原脚本不动**：
   - 新时间越过段落边界（或超出整场范围）
   - 音乐拍点偏差 **超过 80ms**（恰 80ms 不触发）
   - 与同点位前一发间隔 **短于 1.2s**（恰 1.2s 不触发，含已执行前发）
4. 通过校验的变更单进入待确认：**安全负责人与音乐负责人对同一版本均确认后**，才整体生成新签批版本并保留旧版本。
5. 待确认期间修改送审，变更单内容版本 +1，**此前所有确认作废**并留痕，需重新确认。
6. 时间轴、点位图、变更记录实时同步；全部状态（节点、变更单、版本档案）持久化到
   `localStorage`，浏览器重开后仍可查。

## 文件分层

| 文件 | 职责 |
| --- | --- |
| `src/rules.ts` | 业务规则层：预置数据、传播算法、跨段/拍点/间隔校验、指纹（纯函数） |
| `src/store.ts` | 版本存储层：变更单生命周期、双人确认与作废、签批快照、localStorage 持久化、订阅 |
| `src/App.tsx` | 页面交互层：时间轴、点位图、变更编辑、双人确认、变更记录、版本档案 |
